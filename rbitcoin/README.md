# rbitcoin — Umbrel app package (v0.8.0)

Standalone **full Bitcoin node in Rust** (pure-Rust consensus, multi-peer IBD)
with built-in **Electrum** (50001), **Esplora** (3000) and **Core-compatible
RPC** (8332, cookie auth). Modeled on the official Fulcrum package.

## Adapted from Fulcrum
- **No bitcoind dependency** — rbitcoin *is* the full node: no `dependsOn`, no
  `${APP_BITCOIN_DATA_DIR}` mounts, no `BITCOIN_*` env (manifest says so too).
- **Two Tor hidden services** (electrum, esplora — OS-assigned ports); RPC
  stays localhost-only (no Tor).
- **RPC cookie** generated by the entrypoint only when the file is absent, so
  RPC clients (Wasabi/LND) survive restarts: one `user:pass` line, **no
  trailing newline** (the node refuses to start with one).
- **UI**: tiny `nginx:alpine` page (Dockerfile target `ui`), rendered from env
  at container start — replaces Fulcrum's external `app-fulcrum` image.
- Node image built from **verified upstream release binaries**, not a
  third-party image.

## Files
`umbrel-app.yml` (id `rbitcoin`, implements `electrs`) · `docker-compose.yml`
(app_proxy 3012, app UI, rbitcoin node, tor) · `torrc.template` · `Dockerfile`
(targets `node`, `ui`) · this file.

## Binary verification (fail closed)
The Dockerfile `fetch` stage downloads the v0.8.0 release and aborts the
build on any mismatch: the binaries are checked against **hardcoded
SHA-256s** (`2a261a…` node, `abc8ae…` cli) as the primary check, then against
the release's own `SHA256SUMS.linux-musl` (binaries renamed to the short
names the sums file uses, exactly two matching lines required) as a secondary
check; the node binary is also pinned at exactly **17,064,208 bytes**. The
build refuses any architecture other than amd64 (`ARG TARGETARCH` guard).

## Install on Umbrel OS
1. Clone and enter the app directory:
   ```sh
   git clone https://github.com/reya01/rbitcoin_umbrel_experiment.git
   cd rbitcoin_umbrel_experiment/rbitcoin
   ```
2. Pre-create the data dir **before** installing — Docker creates missing
   bind sources root-owned, which would crash-loop the uid-1000 node:
   ```sh
   sudo mkdir -p ~/umbrel/app-data/rbitcoin/data && sudo chown -R 1000:1000 ~/umbrel/app-data/rbitcoin
   ```
3. Build both images on the Umbrel host itself (compose references these
   local tags):
   ```sh
   docker build --target node -t rbitcoin-node:0.8.0 .
   docker build --target ui   -t rbitcoin-ui:0.8.0 .
   ```
4. Copy the app into Umbrel and install it:
   ```sh
   cd ..
   sudo cp -r rbitcoin ~/umbrel/apps/
   ```
   Restart Umbrel, then install rbitcoin from the App Store.

Ports are assigned by Umbrel OS at install time
(`APP_RBITCOIN_{ELECTRUM,ESPLORA,RPC}_PORT`), not the conventional
50001/3000/8332 — read the actual host ports from the app's UI page or from
the compose output on the host (`docker compose ps`):
- UI: the app's page in the Umbrel dashboard
- Electrum (Electrum/Sparrow/Liana/Cake/BlueWallet/BitBox/Envoy): `<umbrel>:<electrum-port>`
- Esplora (BDK/Alby Hub): `http://<umbrel>:<esplora-port>`
- RPC (Wasabi/LND/CLN, Umbrel host only): `127.0.0.1:<rpc-port>`, cookie at
  `~/umbrel/app-data/rbitcoin/data/rbitcoin/.cookie`
- Tor onions: surfaced on the UI page via env (`RBITCOIN_ELECTRUM_ONION`,
  `RBITCOIN_ESPLORA_ONION`); raw hostnames in the tor data dir
  (`app-rbitcoin-electrum/`, `app-rbitcoin-esplora/`).

On the Umbrel host (SSH), watch IBD progress in the node logs — the container
is `rbitcoin-rbitcoin-1` (umbreld's compose project is the app id):
```sh
docker logs rbitcoin-rbitcoin-1 --tail 20
```
or, robustly:
```sh
docker logs "$(docker ps -qf name=rbitcoin-rbitcoin)" --tail 20
```

## Connecting Sparrow Wallet
1. In Sparrow: **Preferences → Server → Private Electrum**.
2. Server: `<umbrel-IP>:<electrum-port>` — use the Umbrel's IP;
   `umbrel.local` often doesn't resolve (especially on Windows).
3. Turn **Use SSL OFF** — the Electrum server is plain TCP.
4. Click **Test Connection**.

Over Tor: paste `<onion>:<electrum-port>` as the server — Sparrow ≥ 1.7
routes `.onion` addresses through its built-in Tor automatically.

**Be patient during IBD:** the Electrum and Esplora servers only answer after
initial block download completes — **days**, not minutes. Until then,
connection attempts (including Sparrow's Test Connection) fail; watch the
logs (command above) for progress. If the UI page shows the onions as "not
available yet" after first install, restart the app once (Tor creates
hostnames asynchronously; the UI renders once at container start).

## RPC — Umbrel host only
RPC is published on `127.0.0.1` only: it is reachable **only by software
running on the Umbrel host itself**. Other Umbrel apps and other computers
cannot reach it — use an SSH port forward if you need RPC from elsewhere
(`ssh -L 8332:127.0.0.1:<rpc-port> umbrel@<umbrel-IP>`). Do **not** open RPC
to the LAN. Auth is the cookie at
`~/umbrel/app-data/rbitcoin/data/rbitcoin/.cookie` (one `user:pass` line, no
trailing newline), created on first start and kept across restarts.

## Troubleshooting
If the node crash-loops on `mkdir`/cookie write (e.g. it was installed before
step 2 above), fix the data dir on the host:
`sudo mkdir -p ~/umbrel/app-data/rbitcoin/data/rbitcoin && sudo chown -R 1000:1000 ~/umbrel/app-data/rbitcoin/data`.

Node runs with `--sh-index --sp-tweaks --block-filter-index` (silent payments +
BIP158 filters built during IBD; filters needed by Wasabi).

## Warnings
- **Disk:** 800 GB minimum, 1 TB+ recommended with the indexes; keep ≥100 GB
  headroom — a disk that fills mid-IBD aborts the node into a restart loop.
  Check with `df -h`.
- Full-archive IBD takes **days**; chain data is in `backupIgnore`.
- `stop_grace_period: 30m` — the node flushes a large store on shutdown.
- **x86_64 only** — v0.8.0 ships linux-musl x86_64 binaries (no aarch64
  asset); the build (`TARGETARCH` guard) and the entrypoint both fail loudly
  on other arches.
